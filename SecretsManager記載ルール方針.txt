### 1. Secrets Manager / Parameter Store の使い分け

* 漏えい時に不正アクセス、なりすまし、データ改ざん、課金被害等につながるシークレット情報は Secrets Manager で管理する。
* 環境名、エンドポイントURL、リソース名、ログレベル等の非機密な設定値は Parameter Store で管理する。
* Parameter Store は SecureString ではなく String を使用する。

### 2. Secrets Manager の作成方針

* シークレット本体は Terraform で作成する。
* シークレット値は Terraform では管理せず、作成後に手動で登録する。
* 自動ローテーションは使用しない。
* 暗号化方式は基本設計書の方針に従う。

### 3. シークレット値の取り扱い

* シークレット値は本一覧には記載しない。
* 実際の値は対象シークレットごとに別途担当者へ連携する。

### 4. シークレット名

* シークレット名は既定の命名規約に従って記載する。

### 5. 記載単位

* 1シークレットキーにつき1行で記載する。
* 同一シークレット内に複数キーがある場合は、シークレット名を同一にして行を分けて記載する。

### 6. 追加・変更時の対応

* 初回記載後に追加・変更が発生した場合は、対象行を追記または更新する。
* 追加・変更箇所は赤字で記載し、Terraform作成担当者へチャット等で連携する。
